# Methods

The pipeline generates findings from the raw input, audits the matches and source interpretations, runs additional calculations, and assembles the report directly. No earlier report or language model is part of that pipeline. Explanations come from attributed source text and explicit explanatory templates.

## Input and matching

The parser normalizes chromosome labels, requires a declared genome build and forward orientation, and preserves missing calls. Conflicting marker IDs or conflicting base calls at the same locus are withheld. The SNPedia matcher separates explicitly identified substitution probes from co-located insertion/deletion probes. An unrelated co-located marker cannot fill an explicit no-call. Autosomal haploid calls and unsupported indel representations stay unresolved.

For header-identified 23andMe exports, the matcher resolves simple **heterozygous** I/D calls only when an exact marker or documented alias has one public ClinVar allele, the SNPedia insertion sequence agrees on the stated strand, and the input position matches a documented source, VCF-anchor or unpadded-event position. A heterozygote contains one of each allele even if a provider reverses the I/D codes. The report retains the original call, decoded sequence, coordinates and public definition.

Homozygous I/D conversions need a provider-specific allele definition to establish which sequence is present. Agreement between ClinVar and SNPedia about a sequence does not establish that assay coding. Without that definition, tentative conversions stay in unresolved context and cannot produce clinical annotations or multi-marker findings. Literal source I/D pages can still be matched at exact source coordinates without conversion. Published coding exceptions, multiple possible alleles, substitutions combined with indels, and repeat-shifted sequences that do not agree also stay unresolved. The matcher does not guess a reversed mapping or use a saved comparison report to select a genotype.

For SNPedia, the importer extracts public coordinates, stabilized orientation, aliases, genotype summaries, magnitude, repute, population templates, citations and genoset descriptions. Unique UCSC chain mappings reconcile nuclear coordinates between GRCh37 and GRCh38. Official mitochondrial coordinates share NC_012920.1 across those assemblies; they are not remapped through UCSC hg19's different mitochondrial sequence. The interpreter requires agreement with the supported source coordinate conventions; explicit build-flip exceptions and ambiguous mappings remain unresolved. Explicit public chip aliases are supported. Strand complements follow the source metadata, never an allele-frequency guess.

A small, non-executing grammar evaluates public genoset criteria: allele/genotype tests, Boolean operations, thresholds and dependent genosets. Missing calls remain unknown, including under negation. Cyclic dependencies and unavailable criteria remain unresolved. Source descriptions are not treated as executable rules.

Reference preparation corroborates SNPedia SNV coordinates against unique rsID placements in ClinVar and the public Ensembl GRCh37 catalogue. Multiple primary placements, complex variants and chromosome conflicts are excluded from the Ensembl correction. Explicit public synonyms can connect merged rsIDs; sharing a coordinate is not sufficient. Corrections retain the original coordinates, method and reference hash.

For eligible SNVs with two source alleles, the importer compares that source allele set with the public forward-strand alleles. Both source alleles must be compatible in exactly one orientation; a unique direct or complementary match establishes the source orientation for GRCh37 independently of the person's genotype. Public records can contain additional SNV alleles, but if both orientations remain possible, the strand remains unresolved. Incomplete or palindromic source allele sets cannot establish a strand. A measured A/T or C/G heterozygote can still be interpreted when its genotype is identical on both strands and compatible with both public allele sets. Homozygous palindromic calls still need valid source orientation. The report shows the coordinate and strand evidence. These rules do not decode ambiguous provider I/D codes.

The report includes unresolved variant context and multi-marker rules. It distinguishes missing markers in unknown rule branches from missing markers in branches whose outcome is already decided. Some unresolved rules have positive observed support but depend on an unavailable exclusion test. A separate conditional section shows those observations and the assumption needed for the rule to pass. It never adds the rule to confirmed findings or substitutes a reference genotype. Rules supported only by absent data are excluded from that section. Source context for an unresolved variant is general literature, not a personal finding.

Source magnitude is an editorial interest rating, not disease probability. General variant discussions are shown separately from the genotype-specific explanation, because not every statement about a marker applies to the observed genotype. Wiki metadata is converted into labelled fields and source prose is displayed as text.

The pipeline retains assay warnings from the actual input probes when they map to canonical rsIDs. Warnings on a probe's genotype pages are labelled as probe context; their disease claims, genotype, magnitude and classification are not inherited. Unreliable-probe and error-prone-call wording appears prominently in the finding and evidence overview, with links to the warning sources. A source warning takes priority over the clinical-review grouping even when a variant has strong review support. This qualifies interpretation without asserting that an individual measurement is wrong.

Two reviewed public probe definitions recover metadata missing from source templates: APP E682K and PSEN1 L173F (G>C). Their exact source-page checksums, ordered allele changes, build-specific placements, allele-registry identifiers and publications are recorded in `genetics_app/data/source_metadata.json`. The [ClinGen Allele Registry](https://reg.clinicalgenome.org/) supplies sequence mappings; the [APP publication](https://doi.org/10.1002/emmm.201100138), [genomic-coordinate study](https://doi.org/10.1016/j.jalz.2015.02.007) and [PSEN1 study](https://doi.org/10.1002/alz.12005) provide supporting variant descriptions. The APP source uses complementary alleles, so its genomic-forward call must be translated before matching source genotype text. Ordered reference/alternate identity establishes the PSEN1 source orientation even though its unordered G/C allele set is palindromic.

Reviewed definitions are genotype-independent and fail closed if source content, source alleles, coordinates or orientation conflict. They establish sequence identity, not clinical reclassification or assay validation. A different alternate allele at the same coordinate is not corroboration. When the target alternate allele is absent from a called genotype, the report says so explicitly and preserves the original source summary in the evidence details. This observation applies only to the assayed site and is not a clearance for the gene or a disease.

## Audit and clinical sources

The pipeline compares generated findings with ClinVar annotations for the same marker identity and retains differences for review. ClinVar matching requires exact coordinates and compatible alternate alleles for SNVs, or the explicitly resolved sequence allele described above for supported indels. Unrelated co-located records are not corroboration. Unsupported complex variants, incompatible calls and somatic-only records are withheld. Source classification, review stars, conditions, conflict text and record links remain available. These variant-level aggregates do not establish an individual's diagnosis, inheritance pattern or penetrance. [ClinVar file scope](https://www.ncbi.nlm.nih.gov/clinvar/docs/ftp_primer/) and [review status](https://www.ncbi.nlm.nih.gov/clinvar/docs/review_status/) describe the source fields.

## Interpretation overview

Evidence summaries group clinically annotated alleles by gene and evidence category. All underlying findings remain in the complete exported report. Pathogenic/likely pathogenic annotations with at least two ClinVar review stars enter the clinical-review group; lower-review records stay separate. This is a transparent navigation threshold, not a validated clinical utility score. Explicit source assay warnings or applicable array-quality flags move those annotations into an assay-caution group. Warnings detected in source prose are source cautions, not independently confirmed measurement failures.

Conflicting classifications and uncertain significance remain separate from disease conclusions. Duplicate annotations are collapsed; multiple sites do not imply compound heterozygosity. Benign annotations remain in the report without producing an overall health clearance. Curated traits retain their actual explanations. Medication-related multi-marker labels are grouped with their observed source patterns and coverage limits; they do not become comprehensive diplotypes or prescribing instructions. The underlying [ACMG/AMP classification framework](https://pubmed.ncbi.nlm.nih.gov/25741868/) and [CPIC guideline](https://files.cpicpgx.org/data/guideline/publication/serotonin_reuptake_inhibitor_antidepressants/2023/37032427.pdf) describe why variant classification, complete genotype interpretation and clinical use are distinct.

All wording is generated from explicit templates and attributed source content. Source magnitude cannot promote a finding to stronger clinical evidence, and citation counts do not become quality scores. The report exposes the supporting variants, classifications, review status, uncertainty and source links for each overview item.

The array-quality analysis compares assayed positions with published GenomePrep array clusters. It applies a cluster's flagged positions only when the best Jaccard similarity is at least 0.5. A flag qualifies the finding; it does not prove a measurement wrong. Flagged sites are excluded from ancestry and imputation inputs and from directly measured score components. SNPedia findings and dependent genosets retain visible flags.

Three separately curated rules cover lactase persistence, ALDH2 and earwax type. They require the expected build-specific coordinates and forward alleles and include their primary sources. GWAS Catalog overlaps are separate literature leads: the app does not infer a personal effect from an rsID overlap. It retains up to 2,000 strongest-p-value leads and shows the total overlap count.

## Ancestry and frequencies

The ancestry analysis intersects measured, compatible, non-palindromic autosomal SNPs with each public panel. PLINK applies minor-allele-frequency and missingness filters, then prunes linkage disequilibrium with a 200-variant window, 20-variant step and r² threshold 0.2. Deterministic thinning caps the panel at 15,000 markers.

Reference allele frequencies standardize the matrix. A reference-only PCA model projects the user's genotype, and distances in ten principal components identify nearby reference samples. Exports retain projection coordinates, nearest-sample counts, reference points and population-centroid distances. These are similarities to sampled groups, not ancestry percentages or nationality.

A stratified reference holdout uses training-only scaling and PCA before a seven-neighbor classifier predicts population labels. That accuracy measures reference-group separation, not confidence in a person's ancestry. Genotype-frequency panels separately count observed matches among called reference samples and show the denominators.

## Lineages

For paternal candidates, the analysis maps assayed Y positions to the public tree's GRCh38 positions, then compares observed bases with ancestral and derived alleles. Candidates require a directly supported terminal marker. The ranking is derived support minus five times ancestral conflicts along the path; it is a transparent heuristic, not a calibrated probability or a complete Y-haplogroup caller. The report retains alternate candidates and conflicting calls rather than selecting a fixed lineage.

For maternal lineage, HaploGrep 3 compares the assayed mitochondrial positions with Phylotree rCRS 17.3. The pipeline supplies only observed positions as the coverage range and reports the top five candidates and their source quality scores. Unassayed positions are not filled with reference alleles. Array coverage can leave several branches compatible.

## Scores, imputation and phasing

The scoring analysis checks measured coverage for PGS000034 (BMI), PGS000019 (CAD) and PGS000297 (height). A direct score is withheld unless every variant has a compatible interpretation. Ambiguous multi-allelic inferred alleles, missing calls, quality flags and unresolved palindromic sites reduce coverage rather than becoming zero-effect alleles.

The BMI analysis uses Beagle 5.5 and public reference haplotypes around all 97 score targets. Overlapping ±1 Mb regions are merged before preparation. Each run creates its own input VCF and inference outputs. Observed compatible calls remain labelled measured; other targets require a genotype posterior of at least 0.99 before their estimated effect-allele dosage contributes. The weighted sum is withheld when coverage is incomplete or a required calculation fails.

The scoring analysis compares a complete sum with scores calculated from the same 503 European reference samples. The percentile is relative to that panel; it is not measured BMI, a validated population percentile, or an absolute risk. In two fixed regions, deterministic masking withholds approximately 20% of compatible measured calls and compares inference with the withheld calls. This checks selected regions, not every inferred site or independent laboratory truth.

The TPMT analysis phases two specified target sites using three seeds. The report includes measured calls, inferred chromosome patterns, genotype posteriors and seed agreement. Genotype posterior is not phase confidence, and seed agreement is computational stability. This does not provide comprehensive diplotypes, copy-number analysis or a prescribing recommendation.

## Reproducibility and privacy

Prepared profiles record public reference hashes, and analysis rejects changed files. Reports retain application/rule versions, reference metadata, input checksum, completion status, calculation details and unresolved cases. A single failed or unsupported stage cannot silently appear as a fully completed pipeline.

The application reads the input directly from a local file. No browser, HTTP server or LLM is involved. Source text is preserved in JSON and rendered as labelled, non-executing text in Markdown and plain-text exports. Terminal control characters are removed from display text. The pipeline removes temporary external-tool files after a run; `--work` explicitly retains them for CLI runs. Ctrl+C cancels active external commands and queued imputation work before cleanup. Completed JSON is saved before optional interactive exports. Existing exports are never overwritten, and report files are created with owner-only permissions. Reports and input checksums are personal data when generated from personal inputs.

Full Promethease feature parity and clinical validation have not been established. Current exclusions include dedicated blood-group reports, multi-person comparison, full topic taxonomy, complex structural variants, and comprehensive pharmacogenetics. Missing source criteria, low coverage and unsupported builds are visible in the report.
